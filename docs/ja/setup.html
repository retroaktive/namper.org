01.1パワーボタン

Rigタブ右上にある緑色のパワーアイコンが、オーディオエンジンの開始と停止を 行います。オンになるまでは何も処理されず、音も鳴りません — メーターは動かず、録音は Audio is off — tap the power button before recording.で拒否されます。

エンジンが停止しているときは暗く表示され、動作中は緑色に光ります。隣にある DSP loadチップは、プロセッサーの負荷を示します: 60 %未満は緑、85 %までは アンバー、それ以上は赤です。赤のままなら、チェーンからブロックを1つ外すか、バッファサイズを 1段階上げてください。

NAMperがマイクへのアクセスを求めるのは起動時ではなく、初めてエンジンを開始したときです。

接続を抜いたとき

ヘッドフォンやインターフェースを抜くとエンジンが停止します — これは意図的な仕様で、 大音量のリグが勝手にスマホのスピーカーへ切り替わることがないようにするためです。差し直したら もう一度パワーをタップしてください。新しい機器を接続すると、エンジンは自動的に再構築されます。

エンジンが起動できない場合、バナーにはAudio could not start. Another app may be using the interface — try again.と表示されます。インターフェースを 使用している他のアプリを閉じてから、もう一度試してください。

01.2オーディオインターフェース

デバイス選択画面はありません。NAMperはiOSが使用しているオーディオルートにそのまま従うため、 ハードウェアの選び方はいつも通りで構いません — インターフェースを接続すれば、アプリが それに合わせて再構築されます。マルチチャンネルインターフェースにも対応し、最大8入力 チャンネルまで扱えます。

設定 → AUDIO INTERFACEで、NAMperが実際に認識している内容がわかります: Sample rate、Inputs、Outputs、 Engine(runningまたはstopped)。 チャンネル数が想定と違う場合は、この項目で確認できます。

チャンネルに名前を付ける

設定 → CHANNEL NAMESでは、各入力にプレースホルダー Guitar, Vocal…付きのテキストフィールドが用意されています。一度名前を 付ければ、アプリ内のすべての入力ピッカー — リグの入力、ルーパートラックのソース、 入力トリムの行 — にその名前が表示されます。名前を付けていないチャンネルは In 1、In 2のように表示されます。

複数の出力

設定 → Use all interface outputsはデフォルトでオフになっており、 ステレオ機器では通常オンにする必要はありません。オンにすると、NAMperはインターフェース上の すべての出力ペアを開くため、リグ、パラレルブランチ、ルーパートラック、メトロノームのクリックが それぞれ専用のペアを持てます — ギターをフロントオブハウスへ、クリックをドラマーの インイヤーへ、といった具合です。

入力チャンネル

Input channelsは通常Autoのままで構いません。 インターフェースが、NAMperに開かせたい数より多くのチャンネルを報告してくる場合にのみ、 数値を固定してください。

01.3メーターとレベル

Rigタブのアンプカードの両脇には、縦型のメーターが2本並びます: 左がIN、 右がOUTです。どちらも下端が−60 dBFS、上端が0で、緑からアンバー、 赤へと変化します。専用のクリップランプはなく、バーが一番上の赤に達した状態がそのまま クリッピングです。

入力レベルを設定する

  1. オーディオをオンにし、普段いちばん強く弾く強さで弾いてみます。
  2. INメーターは上部3分の1まで届き、赤には入らないようにします。
  3. インターフェースにゲインつまみがあればそれを使います。ない場合は設定 → Input trimを開き、そのチャンネルのスライダーを上げてください — −12 dBから+24 dBまで1 dB刻みで動き、初期値は0です。

INメーターはトリム適用後のレベルを示すため、表示されている 値がそのままアンプモデルに入る信号です。

マスターセクション

Rigタブの下部にあるMASTERカードは、すべてのリグ、ルーパー、サンプラー、 バッキングトラックがハードウェア出力の直前で合流する場所です。ステレオのピークバー LとRには−12と−6 dBの目盛りがあり、加えて放送基準 スタイルのラウドネス表示がLUFSで示されます — 大きい数字が瞬間的な ラウドネス、小さい方の線がショートタームの値です。無音時は-infと 表示されます。下のフェーダーは−60から+12 dBの範囲で動きます。

各ブロックのエディタにも小さなIN・OUTメーターが 付いており、どのブロックが負荷過多になっているかを見つける最も手早い方法です。

01.4サンプルレートとバッファ

どちらも設定 → AUDIO INTERFACEにあり、オーディオルートごとに 記憶されます — インターフェースとヘッドフォンで、それぞれ別の設定を保持できます。

サンプルレート

チップにはAuto、44.1k、48k、 88.2k、96k、176.4k、 192kと表示されます。デフォルトはAutoで、単純に インターフェースに追従します。レートを変更するとエンジンが再起動します。

本体のマイクとスピーカーのみを使う場合はAutoと48k しか表示されず、 The built-in audio runs at 48 kHz only. Connect an interface for more rates.という注記が出ます。インターフェースを接続すると全リストが表示されますが — そのインターフェースが一度拒否したレートは、NAMperが記憶して以後表示しません。

レートが拒否されると、アプリは直前のレートに戻り、赤字でこう表示します: This interface doesn't support … Hz — staying at … Hz.

どのレートを使うべきか

高ければ良いというものではありません — 処理の余裕を消費しますし、NAMプロファイルは もともと一般的なレートでキャプチャされています。特定のレートで動くセッションに 合わせる必要がない限り、Autoのままにしておきましょう。

バッファサイズ

Bufferでは64、128、 256、512フレームから選べ、それによって得られる レイテンシがリアルタイムで表示されます。デフォルトは128です。アプリ自身の 説明は明快です: Smaller = lower latency; larger = safer with USB interfaces. Crackling? Go up one step.

これがNAMper唯一のレイテンシ調整項目であり、別途レイテンシ設定はありません。

Bluetooth出力

Bluetoothヘッドフォンやスピーカーはおよそ0.2秒の遅延を追加するため、演奏には 向きません。Bluetoothルートを検出すると、アプリが警告を表示します。ライブ演奏では 有線出力を使ってください。

01.5フィードバックガード

本体のマイクを開いたまま本体のスピーカーで再生するギターアプリは、フィードバックループが 起きるのを待っているようなものです。そこでNAMperはまさにその組み合わせ — 内蔵マイクが 入力、内蔵スピーカーまたは受話口が出力 — を常に監視し、ハウリングが起きる前に出力を ミュートします。

作動するとOutput muted to stop feedback (mic → speaker). Connect an interface or headphones.と表示されます。ミュートされるのは可聴出力 のみで、チューナー、入力メーター、録音はすべて動作を続けるため、音のチューニングも テイクの収録も引き続き行えます。

ヘッドフォンかインターフェースを接続すると、ミュートは自動的に解除されます。バナーの ✕は今回のセッション中だけメッセージを隠すもので、ミュートを解除するわけではありません。

「Unmute」がすること

Unmuteボタンは一時的な例外措置です: このセッション中は出力が 有効のままになりますが、ルートが変化すると — インターフェースやヘッドフォンを抜き差し したり、アプリを再起動したりすると — ガードは再び作動し、内蔵スピーカーは 再び保護されます。ガードを恒久的に無効にするには、設定内の Feedback guardスイッチを使ってください。

スイッチ本体は設定 → AUDIO INTERFACE → Feedback guardにあり、サブタイトルは Mutes the output while the mic plays through the phone speaker.です。 デフォルトでオンになっています。

01.6権限について

NAMperが求める権限は正確に2つだけで、必要になったときにのみ確認します。

権限いつ理由
マイク初めてパワーボタンをタップしたとき ギターやマイクの音を聞くため。確認画面にもはっきり書かれています: 音声が 端末の外に出ることはありません。
Bluetooth初めてワイヤレスMIDIペダルとペアリングするとき Bluetooth MIDIコントローラーを検出・接続するため。

マイクへのアクセスがオフの場合、赤いバナーに Microphone access is off — NAMper can't hear your guitar.と 表示され、SettingsボタンからiOSの設定画面へ直接移動できます。許可すると、 再起動なしでエンジンが再構築されます。

アナリティクスもトラッキングもアカウントもなく、カメラ、写真、位置情報、連絡先への アクセスもありません。NAMperは何も収集しません。

01.7ファイルの保存場所

NAMperが保持するものはすべて、ファイルAppの On My iPhone → NAMper(iPadの場合はOn My iPad)から 確認できます。ファイルAppを使ってファイルを出し入れしたり、フォルダをバックアップしたり、 パソコンへ移動したりできます。

フォルダ中身
tones/NAMアンププロファイル(.nam)と そのカバーアート、メタデータ
irs/インポートしたインパルスレスポンス
samples/サンプラーパッド、および samples/kits/内の保存済みキット
backing/バッキングトラック、セットリスト、歌詞、 プリセットマーカー
recordings/あなたの演奏の録音
presets/リグのプリセット、およびルーパー、サンプラー、 セットリスト、コントロールの各プリセット
engine.logインターフェースのルーティングとピーク レベルを記録したプレーンテキストのログ。バグ報告に便利です
覚えておくと便利なショートカット

ファイルAppでbacking/に直接ドロップした音声ファイルは、次にNAMperを 開いたときにセットリストへ自動的に取り込まれます。パソコン上でのコピー&ペースト1回で セット全体を読み込め、スマホで20回タップする必要はありません。

予想と違う動きをする点が2つあります: ファイルをアプリアイコンやウィンドウにドラッグ することはできず — インポートはすべてNAMper内のファイルピッカー経由になります — またtones/フォルダは意図的にiCloudバックアップの対象外です。 TONE3000からいつでも再ダウンロードできるためです。
